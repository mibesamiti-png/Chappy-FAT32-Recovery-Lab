## New bounded, default-off production-facing adapter

`core/Chappy.FragmentPhysicalReceipts.psm1` exports `Invoke-ChappyA7FragmentPhysicalReceipts -Source [IO.Stream] -EnableA7FragmentReceipts`. With switch OFF it performs no `Read` or `Seek` (no candidate validated). With switch ON it accepts **only a nonwritable readable seekable artificial MemoryStream of 65,536–2,097,152 bytes**, never any file path, device, master IMG, disk, output or repair interface. It reuses `ChappyA7LiveMeterV1` with a new `candidate_validation` phase and **one** shared total cap <=120,000 successful returned physical bytes / <=512 `Read` calls.

Stage 1 calls ACTUAL first-party `Get-ChappyFragmentCandidates` guarded non-oracle 64KiB C scout with original source geometry/correct offsets/SHA withheld. A checks C's self-reported returned bytes against **its own physical Stream.Read meter**. Stage 2 uses the previously accepted A `Resolve-ChappyCandidateDefinitionBoundary` to validate source-token, exact canonical ordered 2-fragment extents, physically nonoverlapping in-range source positions and ambiguities. A's fresh in-process random **ephemeral** token is a source-session label, **not cryptographic authenticity**. Stage 3, for each C-observed structurally consistent candidate, A itself physically `Seek`s and `Read`s each ordered fragment again. The meter records a **new phase** `candidate_validation` actual returned offset+length, and A checks the monotonic physical cursor and total returned length for every fragment. The 65KiB scout-phase read **cannot be reused** as candidate-specific revalidation. Missing/early-zero source, quota, invalid definition or unexpected bytes => UNKNOWN/unattributed, never a verified original.

Output schema `a7_fragment_physical_receipts_v1`; every result `originalIdentity=unknown`, `originalShaVerified=false`, `canSelectOriginal=false`, `canExport=false`, `canRepair=false`. Valid candidates may have `readEvidenceStatus=source_observed` **only meaning the declared physical spans were successfully read under that candidate's A phase, not correct bytes of an original file**. No raw file bytes, private file names, paths or extracted content in results. Scan-versus-revalidation actual/unique/repeated bytes and Read calls are separately recorded. No automatic result confidence promotion or candidate winner.
