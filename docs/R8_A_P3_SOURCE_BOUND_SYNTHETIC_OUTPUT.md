## What R8-P3 newly does

Tag `A3D-standard-202611` is *caller metadata*, **never genuine original-source authentication**.

1. When disabled, return `r8_synthetic_r7_source_binding_v1` status `disabled` before touching source properties, bytes or filesystem. When explicitly enabled, use the real `Get-ChappyA7PublicEvidenceV1`, which delegates to one real protected `ChappyA7LiveMeterV1` and versioned B/C/D + 2-piece actual C candidate physical return observation. This is **R7 A source meter #1** (<=120000 actual returned B, <=512 Read calls). Require exactly ONE source-observed structural 3MF two-piece candidate, original integrity=UNKNOWN, source authenticity not proven, and ordinal two-source-extent candidate ID matching its signed source-bound ordered positions. If 0 or >1 hypothesis or a contradiction occurs, preserve UNKNOWN and **do not output**.
2. A starts a **second independent protected A source meter** on the **same read-only generated MemoryStream** and rereads the two original source-relative candidate extents into a strictly bounded synthetic in-memory projection. The R8 meter #2 cap is <=4096 returned B and <=16 physical Read calls (caller reductions permitted). Each actual positive `Stream.Read` event is checked for source offset, read consumer, returned byte length, and contiguous slice ordering. True 3B return then physical zero, early EOF and quotas mean **UNKNOWN, zero output**. R8 meter #2 actual/unique/repeated and physical calls are reported **separately from R7 meter #1**; the code NEVER merges distinct source-session unique-byte counters or calls both sessions one attested physical source read. The two scans being on the same artificial nonwritable MemoryStream does NOT establish media authenticity, original file identity or immutable original-on-disk bytes.
3. To reuse the previously audited R8 exporter with max 128 KiB caller synthetic byte[], the bridge repacks only the candidate's <=4096 returned bytes into a compact in-memory projection (min 1024B buffer; zero-padding ignored by ordered span lengths) with positions `0..firstLen`, `firstLen..total`. It maintains the original **source-relative R7 candidate ID separately** in the bridge metadata; R8 uses a **different canonical compact projection ID** only for generated safe output basename. Output never includes original filename or original-content private data; root is ONE pre-existing random disposable directory directly under OS temp, no UNC/device/ADS/traversal/junction/reparse ancestor, only atomic `FileMode.CreateNew`, readback SHA and compact *projection* byte[] source digest. Collision/no overwrite, write-failure owned-only cleanup P1/P2 rules are inherited.
4. The returned output SHA is an SHA of generated synthetic candidate bytes and is **NOT an original-file oracle SHA**. R7 structural candidate and R8 synthetic saved candidate are never marked genuine original, winner, true recovered count or export authorized for real data. Public `originalIdentity=unknown`, `originalShaVerified=false`, `canExportOriginal=false`, `canRepairOriginal=false`. No output on source disagreement, missing A public source receipts, >1 candidate, R8 reread failure, unsafe destination or other errors. The bridge returns sanitized status/reason codes, not actual exception payload/source contents.
