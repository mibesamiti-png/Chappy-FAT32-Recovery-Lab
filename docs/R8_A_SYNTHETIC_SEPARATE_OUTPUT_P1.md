## Implemented: `core/Chappy.SyntheticSeparateExportV1.psm1`

New default-OFF `Export-ChappyR8SyntheticCandidateV1` accepts only an in-memory **`byte[] SourceBytes`** capped at 131072 bytes, a caller-supplied **synthetic fixture label** of format `A3D-clean-<number>` / `A3D-standard-<number>`, a canonical `3mf:offset+length,offset+length` candidate ID and two bounded, non-overlapping source-relative extents. It accepts **no source FileStream or source file path**, and the fixture label **is not authenticity proof**. Caller must explicitly set `-EnableSyntheticExport` and provide a distinct `-OutputRoot`. Disabled mode performs no filesystem or source probing.

Destination is restricted to an **already existing, unique, direct child of `[IO.Path]::GetTempPath()`**, named `ChappyR8Synthetic-<32 lowercase hex>`; not any arbitrary user or system folder. The export implementation checks root existence/attributes and refuses a `ReparsePoint` root, relative/traversal/UNC/device/ADS paths, child/nested destinations, caller-declared source/output overlap or nesting, invalid candidate ID/order, overlapping spans, out-of-range source offsets and excessive output size (default 4096B, absolute cap 8192B). It derives its **own** deterministic, safe ASCII output name `candidate-<32 hexadecimal SHA-256 characters of candidate ID>.3mf`, never a caller-supplied filename, and attempts **`FileMode.CreateNew` exclusively**, so a preexisting file is never truncated or overwritten. No source array writes.

The exporter assembles the two artificial source extents into a separate bounded byte array, computes a source digest before and after, flushes the new output to disk, reopens and re-hashes output to verify exact generated candidate-byte equality. The result reports only generated-test output name/path, output SHA, output size and `sourceUnchanged`; always `originalIdentity=unknown`, `originalShaVerified=false`, `originalSourceAuthenticated=false`, `canExportOriginal=false` even when bytes match the generated test-only oracle. A synthetic-only failure injection after writing one chunk tests cleanup **only of an output file successfully created by that invocation**. A previously existing collision is left untouched. No actual original file names or content are used.

**Important limitations requiring further R8 gates:** temporary path and caller-declared source-root checks alone are NOT race-proof source/output disjointness or proof of an authentic original; a malicious process could replace a root or path between validation and create/delete (reparse TOCTOU). This first bounded prototype does NOT permit general local output roots, concurrent hostile junction swap, disk full/write permission failure, unexpected link changes after CreateNew, or 3+ fragment recovery. The test source 64KiB is a synthetic compact track only; standards FAT32 R3 source input is not yet integrated with the R7 live candidate reporter. R8 official 9% and R9/R10 are therefore **not credited**.
