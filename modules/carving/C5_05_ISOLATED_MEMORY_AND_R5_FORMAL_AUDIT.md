## Measurement design: not another global suite memory peak

- The native Team C Windows PowerShell 5.1 suite launches **four fresh, separate PowerShell child processes** with only an enumerated worker mode: R2 normal 3MF pair, R2 CRC-consistent modified central-directory tail, standards-shaped R3 SPC1 and SPC2. Each constructs its fixture **in its own memory**, imports scanner modules, resolves test-only BPB data-window hint, computes its synthetic source SHA, then creates a separate read-only MemoryStream.
- After all those preparations and a full .NET GC collection, a tiny independent C# sampler starts; it polls **GC.GetTotalMemory(false)** for managed live bytes and **Process.PrivateMemorySize64** for that child's private process bytes approximately every 1ms, captures a pre-scanner baseline and final sample, and runs **exactly one C Get-ChappyCarvingCandidateEvidenceV1 invocation** before stopping the sampler. Reports measured baseline/peak/positive-growth samples and native scanner elapsed vs independent Stopwatch elapsed; optionally reports the invoking thread's cumulative allocation via reflection into GC.GetAllocatedBytesForCurrentThread, **never as a peak**.
- A separate test-only MemoryStream subclass measures actual positive Read bytes, unique physical offset union, and Read call counts; the production C-returned counters must equal these independent counters. Candidate/source returned bytes, probes/pairs, validator memory bytes and bounded UNKNOWN decision are checked against each generated artificial R2/R3 fixture. Then and ONLY then the worker-only external scorer assembles candidate bytes to compare against the generated reference-original SHA. The scanner receives no correct original extent, source SHA, FAT chain or oracle positions; changing a metadata tail with matching CRC does not become an original winner.
- The child emits **one sanitized numeric JSON line**. It prints NO source bytes, paths, names, fixture images, raw source hashes, identity tokens, private metadata or samples; parent accepts only allowlisted result codes and check counts. The parent watchdog can terminate a delayed synthetic child after 60 seconds, but cannot change production Stream.Read semantics; a successful worker does not prove a real-media hard deadline.
- Predeclared per-invocation memory **sampled growth** upper checks: 128MiB managed live bytes above baseline; 192MiB private bytes above baseline. This is an **isolated-process sampled invocation-window proxy**, not complete attribution of allocations, exact transient peak or production field memory. It is acceptable for C audit proposal only if A independently finds its attribution strong enough; otherwise C5-05 remains PARTIAL. The child's overall process includes the artificial fixture prepared BEFORE baseline; do not pass the entire R3 image buffer as scanner allocation. Sampling thread's own tiny activity remains in its isolated process and is not deducted or concealed.

## Interpretation and limits

The new sampler records a **real measured high-water of the isolated *worker process* over the scanner invocation**, as well as a managed-live heap sample, after subtracting a pre-scan baseline for reporting. It is **not** a profiler of individual C PowerShell objects or a perfect peak resident-heap measurement; GC can collect between samples, private bytes can be reused, and missed sub-millisecond allocation peaks remain unknown. A complete hard source-call deadline, source authenticity, unobserved windows, original 3MF identity and exact per-instruction memory allocation are **not established**. Do not set any production C status to "peak measured" because this is a test-only measurement. Do not claim unapproved original full R5 stage PASS or award its 15 weighted points before A's separate formal-original roadmap review.

**Safety:** The physical microSD and unique ~31GB master IMG are NOT APPROVED for any reading, hashing, scanning, copying, writing, repair, extraction, export, upload or even synthetic-test fixture loading. Only invented generated in-memory buffers run. No real image, real filename or private source path is committed, logged or opened.
