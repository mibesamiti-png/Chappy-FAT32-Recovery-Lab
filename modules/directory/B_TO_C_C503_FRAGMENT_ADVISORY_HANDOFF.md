## Current production integration boundary

**B source:** `Get-ChappyBDirectoryEvidenceV1` produces bounded, opt-in versioned `b_directory_evidence_v1` with redacted *physically returned directory entry* offset, file size and first cluster plus fully returned directory read spans. Those metadata and spans are **B-unattested observations**, not original ownership, chain, path or SHA. `Compare-ChappyBDirectoryReturnedEvidenceV1` compares against a separately supplied outer event list, without minting A authenticity. Only A's existing source-owned R7 module `core/Chappy.LiveBcdEvidence.psm1` can truly establish event origin *inside the same A execution*, and even that does not authenticate original media.

**C source:** `Get-ChappyFragmentCandidates` in `modules/carving/Chappy.FragmentEvidence.psm1` is C-owned, non-oracle, default-OFF two-fragment 3MF candidate discovery. It currently takes no directory hint argument, scans 65,536 B under max 81,920 B returned source, max 98,304 B in-memory C validator work, 16 pairs, 4 starts, 8 tails, and only returns ZIP/CRC structurally consistent candidates. It does **not** verify original-file identity or select an original. **B does not modify it or any C tests/fixtures**.

**New B-only production-facing component:** `modules/directory/DirectoryFragmentAdvisory.ps1` `Get-ChappyBFragmentAdvisoryV1`, pure metadata-only and default OFF, with bounds of 16 C candidates, 32 B entries, 16 B spans and 256 supplied positive-return events. Only after C has finished its own discovery:
1. Accept C's **existing** two-fragment candidate set unchanged; never supply oracle start, tail, expected file length or hash to the C search.
2. Require B4-04 interval consistency and fully covered actual 32 B directory entry in completed directory cluster. Convert **already observed** first-cluster index plus **observed** FAT32 geometry into an advisory numeric first-fragment location; it must equal C's independently discovered firstOffset to count as an observed first-cluster association. No inferred FAT chain or second-fragment location.
3. Mark each C hypothesis `size_consistent_unattested`, `size_conflict_unknown`, `entry_unobserved_unknown` or `source_coverage_unknown`. These mean only numerical metadata consistency/uncertainty. B returns **indexes only**, not any new file/tail offsets, original names, source content, SHA, reconstructed path, A source token, FAT owner, or selection. No I/O in join.
4. If root data were missing/short or a caller forged complete B spans/parent assertions, **fail closed** with UNKNOWN, preserving C candidates. Numeric 0/partial/attacker size cannot justify rejection of a possible structural C fragment hypothesis.
5. All output `b_fragment_advisory_v1` has `originalIdentity=unknown`, `sourceAuthenticity=not_proven`, `originalSha=not_tested`, `advisoryOnly=true`, `canSelectOriginal=false`, `canExport=false`, `canSelectFatCopy=false`, `additionalSourceReadCalls=0`. **A/C must opt in to any future shared adapter**; there is no merged C hint consumer here.

## Test design (independent scorer and equal-budget comparisons)

New `tests/Test-DirectoryR5FragmentAdvisorySupport.ps1` in the **B runner only**, generated 2MiB FAT32-like source with fixed seed **202611**. A first-party deterministic 3MF ZIP generated at 512 B-aligned cluster4, with a valid second part physically at another location and **one equally valid ZIP/CRC but SHA-different central-directory-metadata decoy**, no scorer-only SHA passed into B/C functions. The actual root directory entry carries the observed numeric start cluster and declared size, not a real fragment chain or known original path.

**Four separate cases:** normally observed size and two CRC-valid tails; corrupted observed size +7; hidden/deleted directory entry; physically reversed start/tail order. **Each case runs C's *same production* function twice** on identical immutable generated source with exactly equal window, probe, source returned bytes and validation byte caps. The first run is C **unassisted**; the second is identical C **with B post-hoc advisory**, not a new C hint parameter. Independent readonly `MeteredStream` records each actual successful source Read byte offset/length/SHA; full synthetic image SHA preserved. C budget/return counts and candidate set must be **identical** in the two runs; extra B directory scan reads measured separately. This isolates the advisory's *information value*, not a hypothetical reduction of C search work or claimed runtime speedup.

Expected from fixed artificial file oracle and independent SHA scorer: **two structurally 3MF/CRC-consistent C hypotheses** per case, one SHA-identical original and one SHA-different. Over eight candidate-unit outcomes: unassisted format-positive **TP4 FP4 FN0 TN0 UNKNOWN0** only under synthetic original-SHA truth; B size-consistency observations on normally observed and physically reversed cases would be **TP2 FP2** (no precision gain, *not* verified original). Corrupt size/hidden directory must **abstain four UNKNOWN units**, not count them as TN/FN or delete C candidates. Overall B advisory positive vs original SHA: **TP2 FP2 FN0 TN0 UNKNOWN4**, deliberately no original-file selection. In the reversed-order case the physical tail can precede the first fragment, and a valid ZIP structure is still not original source ownership. These are **frozen expectations before CI**, not a claim until verified.

**Additional separate adversarial controls:** (i) forged B second completed root cluster despite unchanged actual source events, (ii) forged parent asserted to be verified, (iii) B root read returns 17 of 512 B then genuine zero EOF, (iv) C underquota preflight with zero source reads. All must be UNKNOWN without promoting original identity. Count them separately from eight candidate units.

**Resources:** C per-run cap 81,920 actual returned B and at most 16 pair validations, 65,536 B scout; actual/unique/read calls and C validation bytes as independently metered. B 512 B root / 1,024 B geometry with <=97 B positive returned per `Read`, <=128 calls. Baseline additional B source I/O is **1,536 B and 18 calls per case**; B metadata join itself uses **zero** further reads. Never add B physical returns to the *matched-budget C search* metric and claim search speed improved. Stopwatch/peak OS process memory (if recorded) includes unrelated suite allocations; not isolated algorithm peaks or a hardware-speed claim.

**Interpretation:** The aim is to show that a valid observed file size can coexist with a ZIP CRC-valid but wrong-original alternate continuation; a corrupted size or hidden parent cannot be treated as evidence of absence. B's bounded observation provides useful warnings, but it does NOT remove C's fundamental withheld-start/tail ambiguity, proves no original SHA, and does not finish C5-03/C5-05/C5-06. C can review the contract and choose whether to ask A for integration; A alone owns shared contracts/gate status.
